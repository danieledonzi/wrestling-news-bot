# v95.19.1 Simone report identity guard

## Incident and root cause

On 26 July 2026, Simone bound one WrestlingInc Collision URL to both the Collision and Redemption report keys. The special-event scheduler ran on the event morning, supporting summary text could override the source title/URL, and the publisher lacked a final source-URL invariant.

## Runtime invariants

Special-event nights become due at the configured Europe/Rome time on the next calendar day; weekly schedules are unchanged. Source titles and URLs are authoritative and configured weekly-show identities reject incompatible special-event assignments even when supporting text names that event. Before scraping, translation, or WordPress, the automatic publisher normalizes URLs with the shared integrity helper and blocks a URL bound to multiple report keys in the batch or history. A sole explicit assignment may survive an otherwise ambiguous batch.

Blocked assignments remain unpublished and recoverable. Diagnostics and handoff counters expose identity collisions.
Collision rows are emitted again on later runs while the conflicting assignment remains ready; the pending row is deliberately not marked terminal so a later correct source can recover it.

## Rollback

Revert the v95.19.1 commit. No state migration is required; history remains backward compatible because the guard reads the existing `source_url` and `report_key` fields.

## Explicitly unchanged

Gemini models and prompts, Bob, extraction/readiness, WordPress rendering, Menzo, news publication, scoring, canonical metrics, weekly configuration, special-event registry semantics, rescue/lookback and multi-night behavior are unchanged.
