# OpenWrestlingTV P1.4 — Authoritative Snapshot & Reader Convergence

**Version:** `v95.26_p1_4_authoritative_snapshot_reader_convergence`  
**Baseline:** `ca0fdf1ca9a3d27e94f13570c754047c7203251f`

## Authorities by metric family

The P1.4 snapshot (`v95.26_p1_4_authoritative_snapshot.v4`) is the common read model. `canonical_event_ledger.jsonl` is authoritative for canonical run, stable-content lifecycle, editorial-stage, P1.3 AI lifecycle, warning/blocker, Publisher, and Simone facts. `canonical_artifact_index.jsonl` is authoritative for retained-material existence, identity, semantic role, path, representation, provenance, and authority claims. `gemini_call_ledger.jsonl` remains authoritative only for provider usage, token, price, and cost evidence; its `operation_id` is never treated as a logical request ID and no unsupported request-cost join is made. Master-log and current snapshots are explicitly legacy diagnostic/fallback evidence and cannot replace canonical values.

## Coverage, windows, and zero

Every major section reports `available`, `coverage`, `complete_window`, `source`, `schema_version`, `policy_version`, and `diagnostic_mismatches`. Coverage is section-specific: P1.1 run/content/editorial/publication lifecycle, P1.3 core AI operations, full-active-AI operations, P1.3 warning occurrences, P1.3 terminal/recovered failures, and P1.2 artifacts have independent cutover evidence. Native P1.3 events or the known P1.3 boundary commit establish core P1.3 deployment; older P1.1 rows never make P1.3 complete. Aggregate AI totals require observable P1.4 `report_translation` request evidence, so they conservatively remain partial/unavailable before that call site is demonstrably instrumented. `full` means the relevant family began no later than the requested boundary, `partial` means its cutover lies inside the window, and `unavailable` means no dated/readable family evidence exists or the cutover is after the window end. Partial or missing canonical facts are `null`, never zero. A fully covered post-cutover quiet window can emit zero. There is no backfill or ledger rewrite.

Every decoded canonical event is validated against frozen A2. Any malformed JSON row or schema/conditional violation is an integrity failure for every event-backed authoritative section: coverage becomes unavailable and all value-bearing totals and identity sets are suppressed rather than computed from the remaining rows. Partial P1.1 windows likewise expose no nested authoritative event counts or content-ID sets.

Both 24-hour and 72-hour funnels apply the requested UTC boundaries to event timestamps. Each funnel metric retains event count and distinct `content_id` count. Repeated observations and cross-run repeats therefore remain visible without inflating unique content. Per-content lifecycle evidence preserves changing dispositions. Reason-code distributions are retained. Frozen A2 does not distinguish every Massy universe component or duplicate horizon; those fields carry explicit unavailability reasons rather than legacy aggregate substitutions.

## Artifact-chain rules

The central reader resolves only by `content_id`, then selects one coherent `correlation_id`/run-content chain instance (preferentially the deterministic instance containing final publication material) and validates the manifest, indexed path, hash/size, declared format, semantic roles, artifact schema, and authority claims. Roles are never borrowed from another run. Artifact coverage counts only rows whose indexed bytes exist and pass size, SHA-256, format, and role-representation checks; failures remain diagnostic mismatches. Index filesystem/read errors fail open as `canonical_artifact_index_unreadable`. Authoritative artifact counts are emitted only for full windows, never for partial observations. It exposes source material, Bob/Alfred translated candidate, Alfred quality review, and final Publisher retained material where indexed in that instance. P1.2 final material remains `supporting`; it is not upgraded to exact WordPress HTML. Missing roles state `canonical_role_not_indexed:<role>`. Duplicate titles or slugs never cross-link content. Simone report material returns `p1_2_report_material_retention_out_of_scope`, reflecting the P1.2 scope boundary.

## Report-translation telemetry closure

Each existing report chunk/batch creates one `OperationalAIRequest` with `model_role=report_translation`. Its unchanged provider chain shares one logical request ID. Only real provider calls create sequential, 1-based attempts and started/completed/failed events, including monotonic `latency_ms`. Fallback emits `fallback_started` on that same request. Cooldown skips emit avoided telemetry but no attempt and do not increment the attempt number. A missing API key closes the visible intention as a pre-attempt terminal initialization failure while preserving the existing exception. Invalid JSON is a validation failure; provider exceptions are upstream failures; the final available attempt is terminal. Legacy Gemini usage/cost recording is unchanged. Initialization and telemetry remain fail-open and no provider call, prompt, output, batching, cooldown, or exception behavior is changed.

Logical AI windows are owned by `logical_ai_request_created`: requests created inside the requested window are selected, and all available lifecycle rows for those IDs are analyzed, including a terminal row immediately beyond the display boundary. A selected request with an unclosed concrete attempt makes lifecycle metrics unavailable rather than authoritative. The P1.4 mapping is `real_attempts=model_attempts_started`, `successful_attempts=model_attempts_completed`, and `failed_attempts=model_attempts_failed`.

A request-level `stage_failed` with `error_terminal=true` counts as one terminal logical-request failure even when no model attempt exists. Terminal request identities are deduplicated, so corroborating terminal stage and attempt evidence cannot double-count one request.

## Reader migration and diagnostic boundary

`observability_snapshot.py` supplies the P1.4 canonical sections. Daily Editorial Judgment consumes complete-window run, publication, funnel, Alfred, AI-operation, Publisher, and Simone values; once family metadata is present, an incomplete family clears the corresponding serialized `canonical_*` payload rather than retaining master-log values. An incomplete P1.1 window also forces headline run/news/report totals, day type, and overall judgment to `n.d.` instead of deriving classifications from legacy or unknown-as-zero inputs. Translation Quality Audit derives eligibility from complete P1.1 canonical publication content IDs, then uses legacy records only to enrich matching identities and P1.2 only to supply materials; complete canonical publication evidence works even without a master log. When publication authority is unavailable, the artifact index never seeds the fallback population; existing legacy diagnostic discovery remains responsible for establishing it. Translation Warning Analysis continues purpose-specific linguistic analysis over that audit. `send_daily_report.py` renders the Daily Judgment canonical payload and preserves `null` as `n.d.`. Existing legacy values remain visible only as diagnostics and never override complete canonical metrics.

## Consistency invariants

News/report publication counts, Menzo handoffs, warning articles/events/occurrences, blockers, logical requests/attempts, recovered/terminal failures, Publisher failures, Simone outcomes, and artifact availability have one snapshot meaning. A downstream publication cannot be reconciled against an unrelated legacy zero. Legacy Simone errors and identity collisions are not terminal failures. Warning occurrences mean individual `warning_recorded` rows; warning events mean distinct warning-bearing `(run_id, content_id)` reviews; articles with warnings mean distinct content identities. Partial P1.3 or full-active-AI coverage cannot produce an authoritative zero.

## Explicit non-behavioral scope

P1.4 is measurement-only. It changes no selection, dedupe, budget/cap, softpool, prompt, translation, model routing/chain, provider-call count, category, WordPress, publication, report choice, schedule, workflow, or retention behavior. The frozen A2 event and A3 artifact schemas are unchanged. Canonical observation remains fail-open. No historical data is backfilled and no deployment/runtime-service change is included.
